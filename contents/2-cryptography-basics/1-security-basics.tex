In many cases, technical papers include the analysis on the key question: ``How secure is this cryptographic algorithm?'' or rather ``Why this cryptographic algorithm is secure?''. 
In this section, we will shortly describe the notation and typical construction for justifying the security of cryptographic algorithms.

Typically, the cryptographic security is defined in a form of a game between the adversary (who we call $\mathcal{A}$) and the challenger (who we call $\mathcal{C}h$). 
The adversary is trying to break the security of the cryptographic algorithm using arbitrary (but still efficient\footnote{Further, \emph{efficient} means that an algorithm requires polynomial time and memory with respect to the security parameter (which we will define below).}) protocol, while the challenger is following a simple, fixed protocol. 
The game is played in a form of a challenge, where the adversary is given some information and is asked to perform some task. 
The security of the cryptographic algorithm is defined based on the probability of the adversary to win the game.

Certain problems described using idea above form the basis of assumptions that we believe to be secure (for example, discrete logarithm assumption which we will describe further).
When constructing protocols and defining their security notions, we rely on the security of these basic problems.
More specifically, using the notion of \emph{security reductions}, we can prove that a certain protocol is secure if the underlying basis problem is secure.

This section is dedicated to:
\begin{enumerate}
    \item demonstrating how to define the notion of security (\Cref{subsec:defining-security});
    \item showing how to prove that some construction is secure given some specific assumption (\Cref{subsec:security-reduction});
    \item defining key group-based assumptions using developed toolkit (discrete logarithm and Diffie-Hellman assumptions, \Cref{subsec:group-based-assumptions}).
\end{enumerate}

For fulfilling first two goals we will use arguably the most basic cryptographic primitive: \emph{symmetric encryption scheme}.

\subsection{Defining Security}\label{subsec:defining-security}
Let us get into specifics. Suppose that we want to specify that the encryption scheme is secure. Recall that 
cipher $\mathcal{E} = (E,D)$ over the space $(\mathcal{K}, \mathcal{M}, \mathcal{C})$ (here, $\mathcal{K}$ is 
the space containing all possible keys, $\mathcal{M}$ --- all possible messages and $\mathcal{C}$ --- all 
possible ciphers) consists of two efficiently computable methods:
\begin{itemize}
    \item $E: \mathcal{K} \times \mathcal{M} \to \mathcal{C}$ --- encryption method, that based on the provided message $m \in \mathcal{M}$ and key $k \in \mathcal{K}$ outputs the cipher $c = E(k,m) \in \mathcal{C}$.
    \item $D: \mathcal{K} \times \mathcal{C} \to \mathcal{M}$ --- decryption method, that based on the provided cipher $c \in \mathcal{C}$ and key $k \in \mathcal{K}$ outputs the message $m = D(k,c) \in \mathcal{M}$.
\end{itemize}

Of course, we require the \textbf{correctness}:
\begin{equation*}
    D(k,E(k,m)) = m \; \commentgray{for all messages $m \in \mathcal{M}$ and all keys $k \in \mathcal{K}$.}
\end{equation*}

Now let us play the following game between adversary $\mathcal{A}$ and challenger $\mathcal{C}h$ (see \Cref{fig:semantic-security-def} for illustration):
\begin{algoen}
    \item $\mathcal{A}$ picks two messages $m_0,m_1 \in \mathcal{M}$ of the same length on his choice.
    \item $\mathcal{C}h$ picks a random key $k \leftarrowS \mathcal{K}$ and random bit $b \leftarrowS \{0,1\}$ and sends the cipher $c = E(k,m_b)$ to $\mathcal{A}$.
    \item $\mathcal{A}$ is trying to guess the bit $b$ by using the cipher $c$.
    \item $\mathcal{A}$ outputs the guess $\widehat{b}$.
\end{algoen}

Now, what should happen if our encryption scheme is secure? The adversary should not be able to guess the bit $b$ with a probability significantly higher than $1/2$ (a random guess). Formally, define the 
\textbf{advantage} of the adversary $\mathcal{A}$ as:
\begin{equation*}
    \textsf{Adv}^{\textsf{SS}}_{\mathcal{A},\mathcal{E}} := \left| \Pr[\widehat{b} = b] - \frac{1}{2} \right|.
\end{equation*}

We say that the encryption scheme is \textbf{semantically secure}\footnote{This version of definition is called a 
\textbf{bit-guessing} version.} if for any efficient adversary $\mathcal{A}$ the advantage $\textsf{Adv}^{\textsf{SS}}_{\mathcal{A},\mathcal{E}}$ 
is \emph{negligible}. In other words, the adversary cannot guess the bit $b$ with a probability significantly higher than~$1/2$.

However, now we have a reasonable question: what is $\textsf{Adv}^{\textsf{SS}}_{\mathcal{A},\mathcal{E}}$ specifically?
Consequently, what do we mean by ``negligible'' in this context?
Currently, for fixed scheme $\mathcal{E}$, $\textsf{Adv}^{\textsf{SS}}_{\mathcal{A},\mathcal{E}}$ is just a single number.
\emph{In practice}, when this number is below $2^{-128}$, the scheme is commonly considered to be secure\footnote{Such probability very roughly corresponds to National Institute of Standards and Technology (NIST) Category 1: meeting all NIST criteria for Category 1 is generally taken as evidence of security.}.
However, for theoretical analysis, perceiving $\textsf{Adv}^{\textsf{SS}}_{\mathcal{A},\mathcal{E}}$ as a specific number is not convenient for many reasons.
It turns out that a much more fruitful approach is to consider $\textsf{Adv}^{\textsf{SS}}_{\mathcal{A},\mathcal{E}}$ as a function of the ``logarithmic size'' of the scheme, which is denoted by $\lambda \in \mathbb{N}$ and formally called a \textit{security parameter}.
For example, $\lambda$ might correspond to the logarithm of the order of the underlying finite field or, in our case, we might set $\lambda := \text{``ciphertext size in bits''}$.

By thinking of $\textsf{Adv}^{\textsf{SS}}_{\mathcal{A},\mathcal{E}}$ as a function $\mathbb{N} \to \mathbb{R}_{\geq 0}$, we can give the following definition of \textit{negligibility}.

\begin{definition}
    A function $f: \mathbb{N} \to \mathbb{R}$ is called \textbf{negligible} if for all $\gamma \in \mathbb{R}_{>0}$ there exists $n_{\gamma} \in \mathbb{N}$ such that for any $n \geq n_{\gamma}$ we have $|f(n)| < 1/n^{\gamma}$.
\end{definition}

Less formally: $f$ decays faster than any polynomial. 
The alternative definition, which is problably easier to interpret (depending on your mathematical background), is what follows.

\begin{theorem}
    A function $f: \mathbb{N} \to \mathbb{R}$ is \textbf{negligible} if and only if for any $\gamma \in \mathbb{R}_{>0}$, we have
    \begin{equation*}
        \lim_{\lambda \to \infty} f(\lambda)\lambda^{\gamma} = 0.
    \end{equation*}
\end{theorem}

\begin{example}
    The function $f(\lambda) = 2^{-\lambda}$ is negligible since for any $\gamma \in \mathbb{R}_{>0}$ we have
    \begin{equation*}
        \lim_{\lambda \to \infty} 2^{-\lambda}\lambda^{\gamma} = 0.
    \end{equation*}

    The function $g(\lambda) = \frac{1}{\lambda!}$ is also negligible for similar reasons.
\end{example}

\begin{example}
    The function $h(\lambda) = \frac{1}{\lambda}$ is not negligible since for $\gamma = 1$ we have
    \begin{equation*}
        \lim_{\lambda \to \infty} \frac{1}{\lambda} \times \lambda = 1.
    \end{equation*}
\end{example}

This way, we say that some cryptographic scheme is secure if some advantage (for instance, $\textsf{Adv}^{\textsf{SS}}_{\mathcal{A},\mathcal{E}}(\lambda)$), as a function of security parameter $\lambda$, decays faster than any polynomial.
For instance, if $\textsf{Adv}^{\textsf{SS}}_{\mathcal{A},\mathcal{E}}(\lambda)=2^{-\lambda/2}$ for some cipher $\mathcal{E}$, the scheme is semantically secure.

However, many cryptographic papers avoid such explicit definitions as was illustrated in \Cref{fig:semantic-security-def}.
Here is another way to write the same security definition.

\begin{definition}\label{def:semantic-security}
    The encryption scheme $\mathcal{E}$ with a security paramter $\lambda \in \mathbb{N}$ is \textbf{semantically secure} if for any efficient adversary $\mathcal{A}$ we have:
    \begin{equation*}
        \left|\text{Pr}\left[
            b = \widehat{b}
            \;\middle|\;
        \begin{aligned}
            &m_0, m_1 \gets \mathcal{A}(\cdot) \\
            &k \leftarrowS \mathcal{K} \\
            &c_i \gets E(k,m_i), i \in \{0,1\}\\
            &b \leftarrowS \{0,1\}, \widehat{b} \gets \mathcal{A}(c_b) \\
        \end{aligned}\right] - \frac{1}{2}\right| = \text{negl}(\lambda)
    \end{equation*}
\end{definition}

You shall not be afraid of such complex notation; it is in fact quite simple. Notation $\text{Pr}[A \mid B]$ means ``the probability of $A$, given that $B$ occurred''. So our inner probability is read as ``the probability that the guessed bit $\widehat{b}$ equals $b$ given the setup on the right''. 
Then, on the right we define the setup: first the adversary $\mathcal{A}$ generates two messages $m_0,m_1$, then the challenger chooses a random bit $b$ and a key $k$, cipher the message $m_b$, send it to the adversary and the adversary, based on provided cipher $c_b$, gives his guess $\widehat{b}$ as an output. 
We then claim that the probability of the adversary to guess the bit $b$ is close to $1/2$.

Let us see some more examples of how to define the security of certain cryptographic objects.

\subsection{Security Reductions}\label{subsec:security-reduction}

Essentially, message recovery attacks \cite[chapter 2]{Dan_Boneh_2023} are types of attacks that, from given ciphertext, recover the message with significantly better probability than random guessing, which is obviously $1/\#\mathcal{M}$.
Of course, any reasonable notion of security should rule out such an attack, and indeed, semantic security does.

Although this might seem intuitively obvious, we provide a formal proof to clarify the reasoning. 
One of the reasons for doing this is to thoroughly demonstrate the concept of a \emph{security reduction}, which is the primary method used to assess the security of systems.

Let us play the following message recovery attack game between adversary $\mathcal{A}$ and challenger $\mathcal{C}h$.
For a given cipher $\mathcal{E} = (E, D)$, defined over $\mathcal{K}, \mathcal{M}, \mathcal{C}$, and for a given adversary $\mathcal{A}$, the attack game proceeds as follows: 

\begin{algoen}
    \item The challenger computes $m \leftarrowS \mathcal{M}$, $k \leftarrowS \mathcal{K}$, $c \gets E(k, m)$ and sends $c$ to the adversary.
    \item The adversary outputs a message $\widehat{m} \in \mathcal{M}$.
\end{algoen}

We say that $\mathcal{A}$ wins the game if $m=\widehat{m}$, and we define $\mathcal{A}$'s message recovery advantage with respect to $\mathcal{E}$ as\footnote{In most practical applications, $\#\mathcal{M}$ is \textit{super-poly} with respect to $\lambda$ (\textit{i.e.}, $1/\#\mathcal{M}=\text{negl}(\lambda)$). Consequently, defining $\textsf{Adv}^{\textsf{MR}}_{\mathcal{A},\mathcal{E}}(\lambda) := \text{Pr}[\widehat{m}=m]$ is also technically correct for large enough $\mathcal{M}$.}:

\begin{equation*}
    \textsf{Adv}^{\textsf{MR}}_{\mathcal{A},\mathcal{E}}(\lambda) := \left|\text{Pr}[\widehat{m} = m] - \frac{1}{\#\mathcal{M}}\right|.
\end{equation*}

\begin{definition} [Security against message recovery]
    A cipher $\mathcal{E}$ is said to be \emph{secure against message recovery} if for all efficient adversaries $\mathcal{A}$, the function $\textsf{Adv}^{\textsf{MR}}_{\mathcal{A},\mathcal{E}}(\lambda)$ is $\text{negl}(\lambda)$.
\end{definition}

We shall now prove the following reduction.

\begin{theorem}
    Let $\mathcal{E} = (E, D)$ be a cipher defined over $(\mathcal{K}, \mathcal{M}, \mathcal{C})$. If $\mathcal{E}$ is semantically secure then $\mathcal{E}$ is secure against message recovery.
\end{theorem}

\begin{proof}
Let $\mathsf{A}:=$ ``\textcolor{gray!80!black}{$\mathcal{E}$ is semantically secure}'' while $\mathsf{B}:=$ ``\textcolor{gray!80!black}{$\mathcal{E}$ is secure against message recovery}''.
The theorem asks to prove $\mathsf{A} \Rightarrow \mathsf{B}$. 
However, proving this statement is very complicated.
Indeed, both statements require some advantage to be negligible for \textit{all} possible efficient adversaries.
On the other hand, proving the opposite statements (either $\neg\mathsf{A}$ or $\neg\mathsf{B}$) is significantly easier.
For example, $\neg\mathsf{A}=$ ``\textcolor{gray!80!black}{there exists an adversary $\mathcal{A}$ that breaks a semantic security of $\mathcal{E}$}''.
Such a statement, in turn, requires merely providing a single efficient adversary that yields a non-negligible advantage in the game defined previously.

The key idea behind the \emph{security reduction} is the following logical identity:
\begin{equation*}
    (\mathsf{A} \Rightarrow \mathsf{B}) \iff (\textcolor{oc-blue-7}{\neg\mathsf{B} \Rightarrow \neg\mathsf{A}}).
\end{equation*}

So in other words, our key statement reduces to the following: ``given an efficient adversary $\mathcal{A}$ who breaks the message recovery property, show that there exists an adversary $\mathcal{B}$ who breaks the semantic security.''
Notice that while constructing $\mathcal{B}$, we might use $\mathcal{A}$ as a black-box algorithm that somehow solves one of the assumptions (the security of which is typically proven).
A more formal and fancier way to say this is ``$\mathcal{B}$ uses $\mathcal{A}$ as an oracle'' and is denoted by $\mathcal{B}^{\mathcal{A}}$.

Now, here is how we can construct $\mathcal{B}$ specifically:
\begin{algoen}
    \item Adversary $\mathcal{B}$ generates $m_0, m_1 \in \mathcal{M}$ and sends them to the semantic security challenger (see game described in \Cref{fig:semantic-security-def}).
    \item The semantic security challenger sends a ciphertext $c$ to adversary $\mathcal{B}$. Since $\mathcal{B}$ can use 
    the message recovery oracle, it sends $c$ to $\mathcal{A}$. 
    \item $\mathcal{A}$ returns $\widehat{m}$. If $\widehat{m} = m_0$, then output $\widehat{b} := 0$; otherwise, $\widehat{b} := 1$.
    \item $\mathcal{B}$ sends $\widehat{b}$ to the semantic security challenger. 
\end{algoen}

One can show that in such case $\textsf{Adv}^{\textsf{SS}}_{\mathcal{A},\mathcal{E}} = \textsf{Adv}^{\textsf{MR}}_{\mathcal{A},\mathcal{E}}$, proving that $\mathcal{B}$ breaks the semantic security with a non-negligible probability.

\end{proof}

Here is a small ``recipe'' of the idea described above for a more general scenario.

\begin{proposition}[Security Reduction]
    Suppose we have a cryptosystem $\mathcal{E}$ and we believe the problem $\mathcal{X}$ is computationally hard.
    Here is how we typically prove that $\mathcal{E}$ is secure based on $\mathcal{X}$:
    \begin{algoen}
        \item Assume there exists an efficient adversary $\mathcal{A}$ who breaks cryptosystem $\mathcal{E}$ with a non-negligible probability $\varepsilon(\lambda)$.
        \item We construct an efficient algorithm $\mathcal{B}$, which we call the
        \textbf{reduction}, that will solve the computationally hard problem
        $\mathcal{X}$ while using an oracle access to $\mathcal{A}$. Specifically, for any
        input $x$ of the problem $\mathcal{X}$, the algorithm $\mathcal{B}$
        generates the input to the security game of the cryptosystem $\mathcal{E}$, uses $\mathcal{A}$ as a black-box, obtains some output, and tries to use it to solve $\mathcal{X}$.
        \item If $\mathcal{B}$ is constructed properly, the probability of $\mathcal{B}$ solving $\mathcal{X}$ is typically at least $\varepsilon(\lambda)/\lambda^{\gamma}$ for some $\gamma$, which is a non-negligible quantity.
        \item Since we constructed an efficient adversary $\mathcal{B}$ who efficiently breaks $\mathcal{X}$ based on $\mathcal{A}$, we infer that assumption $\mathcal{X}$ implies security of $\mathcal{E}$.
    \end{algoen}
\end{proposition}

\subsection{Group-based Assumptions}\label{subsec:group-based-assumptions}

In this section we will formally define group-based assumptions, which are one of the most central assumptions in the pre-quantum cryptography.
Further fix some group $\mathbb{G}$. 
All subsequent definitions are valid for \textit{any} group, but in practice we will substitute $\mathbb{G}$ with a \emph{group of points on some elliptic curve} (this group will be formally defined in \Cref{section:elliptic-curves}) since such group is believed to be the most suitable for all subsequent assumptions to be hard.

\subsubsection{Discrete Logarithm Assumption}

Now, let us define the fundamental assumption used in cryptography formally: the \textbf{Discrete Logarithm Assumption} (DL) \cite[chapter 16]{Dan_Boneh_2023}.

\begin{definition}
    Assume that $\mathbb{G}$ is a cyclic group of prime order $r$ generated by $g \in \mathbb{G}$. 
    Further assume $r=\Theta(2^{\lambda})$.
    Define the following game:
    \begin{algoen}
        \item Both challenger $\mathcal{C}h$ and adversary $\mathcal{A}$ take a description $\mathbb{G}$ as an 
        input: order $r$ and generator $g \in \mathbb{G}$.
        \item $\mathcal{C}h$ computes $\alpha \leftarrowS \mathbb{Z}_r, u \gets g^{\alpha}$ and sends 
        $u \in \mathbb{G}$ to $\mathcal{A}$.
        \item The adversary $\mathcal{A}$ outputs $\widehat{\alpha} \in \mathbb{Z}_r$.
    \end{algoen}

    We define $\mathcal{A}$'s \textbf{advantage in solving the discrete logarithm problem in $\mathbb{G}$}, 
    denoted as $\text{Adv}^{\text{DL}}_{\mathcal{A},\mathbb{G}}$, as the probability that $\widehat{\alpha} = \alpha$.
\end{definition}

\begin{definition}
    The \textbf{Discrete Logarithm Assumption} holds in the group $\mathbb{G}$ 
    if for any efficient adversary $\mathcal{A}$ the advantage $\text{Adv}^{\text{DL}}_{\mathcal{A},\mathbb{G}}(\lambda)$ 
    is negligible in $\lambda$.
\end{definition}

Informally, this assumption means that given $u$, it is very hard to find $\alpha$ such that $u = g^{\alpha}$. 
Using tools from the previous sections, we now defined this formally.

\subsubsection{Computational Diffie-Hellman}

Another fundamental problem in cryptography is the \textbf{Computational Diffie-Hellman} (CDH) problem \cite[chapter 16]{Dan_Boneh_2023}. 
It states that given $g^{\alpha},g^{\beta}$ it is hard to find $g^{\alpha\beta}$. This property is frequently used 
in the construction of cryptographic protocols such as the Diffie-Hellman key exchange.

Let us define this problem formally.

\begin{definition}
    Define the following game:
    \begin{algoen}
        \item Both challenger $\mathcal{C}h$ and adversary $\mathcal{A}$ take a description $\mathbb{G}$ as an input: specifically, an order $r=\Theta(2^{\lambda})$ and generator $g \in \mathbb{G}$.
        \item $\mathcal{C}h$ computes quantities $\alpha, \beta \leftarrowS \mathbb{Z}_r, u \gets g^{\alpha}, v \gets g^{\beta}, w \gets g^{\alpha\beta}$ and sends $u,v \in \mathbb{G}$ to $\mathcal{A}$.
        \item The adversary $\mathcal{A}$ outputs $\widehat{w} \in \mathbb{G}$.
    \end{algoen}

    We define $\mathcal{A}$'s \textbf{advantage in solving the computational Diffie-Hellman problem in $\mathbb{G}$}
    as $\text{Adv}^{\text{CDH}}_{\mathcal{A},\mathbb{G}}(\lambda) := \Pr[\widehat{w} = w]$.
\end{definition}

\begin{definition}
    The \textbf{Computational Diffie-Hellman Assumption} holds in the group $\mathbb{G}$ if for any efficient 
    adversary $\mathcal{A}$, $\text{Adv}^{\text{CDH}}_{\mathcal{A},\mathbb{G}}(\lambda)=\text{negl}(\lambda)$.
\end{definition}

\subsubsection{Decisional Diffie-Hellman}

Now, we loosen the requirements a bit. The \textbf{Decisional Diffie-Hellman} (DDH) problem \cite[chapter 16]{Dan_Boneh_2023} 
states that given $g^{\alpha},g^{\beta},g^{\alpha\beta}$ it is ``hard'' to distinguish $g^{\alpha\beta}$ from a 
random element in $\mathbb{G}$. Formally, we define this problem as follows.

\begin{definition}
    Define the following game:
    \begin{algoen}
        \item Both challenger $\mathcal{C}h$ and adversary $\mathcal{A}$ take a description $\mathbb{G}$ as an input: order $r=\Theta(2^{\lambda})$ and generator $g \in \mathbb{G}$.
        \item $\mathcal{C}h$ computes $\alpha, \beta,\gamma \leftarrowS \mathbb{Z}_r, u \gets g^{\alpha}, v \gets g^{\beta}, w_0 \gets g^{\alpha\beta}, w_1 \gets g^{\gamma}$. Then, $\mathcal{C}h$ flips a coin $b \leftarrowS \{0,1\}$ and sends $(u,v,w_b)$ to $\mathcal{A}$.
        \item The adversary $\mathcal{A}$ outputs the predicted bit $\widehat{b} \in \{0,1\}$.
    \end{algoen}

    We define $\mathcal{A}$'s \textbf{advantage in solving the Decisional Diffie-Hellman problem in $\mathbb{G}$}, denoted as $\text{Adv}^{\text{DDH}}_{\mathcal{A},\mathbb{G}}(\lambda)$, as
    \begin{equation*}
        \text{Adv}^{\text{DDH}}_{\mathcal{A},\mathbb{G}}(\lambda) := \left| \Pr[b = \widehat{b}] - \frac{1}{2} \right|.
    \end{equation*}
\end{definition}

As mentioned earlier, DDH assumption is considerably \emph{stronger} than CDH.
It is far more fragile and fails even in seemingly straightforward settings, such as any cyclic group of even order (this condition is satisfied by, \textit{e.g.}, $\mathbb{Z}_p^{\times}$ for any odd prime $p$, since $\#\mathbb{Z}_p^{\times} = p-1$).
Consider the following theorem which we prove as an exercise.

\begin{theorem}
    Suppose that $\mathbb{G}$ is a cyclic group of even order. Then, the Decision
    Diffie-Hellman Assumption does not hold in $\mathbb{G}$. In fact, there is an efficient adversary $\mathcal{A}$ 
    that can distinguish $g^{\alpha\beta}$ from a random element in $\mathbb{G}$ with an advantage $1/4$.
\end{theorem}

\begin{proof}
If $\#\mathbb{G}=2n$ for $n \in \mathbb{N}$, it means that we can split the group into two subgroups 
of order $n$, say, $\mathbb{G}_1$ and $\mathbb{G}_2$. The first subgroup consists of elements in a form $g^{2k}$, 
while the second subgroup consists of elements in a form $g^{2k+1}$.

Now, if we could efficiently determine, based on group element $g \in \mathbb{G}$, whether $g \in \mathbb{G}_1$ or 
$g \in \mathbb{G}_2$, we essentially could solve the problem. Fortunately, there is such a method! Consider the 
following lemma.

\begin{lemma}
    Suppose $u=g^{\alpha}$. Then, $\alpha$ is even if and only if $u^n = 1$.
\end{lemma}

\textbf{Proof.} If $\alpha$ is even, then $\alpha = 2\alpha'$ and thus
\begin{equation*}
    u^n = (g^{2\alpha'})^n = g^{2n\alpha'} = (g^{2n})^{\alpha'} = 1^{\alpha'} = 1.
\end{equation*}

Conversely, if $u^n = 1$ then $u^{\alpha n}=1$, meaning that $2n \mid \alpha n$, implying that $\alpha$ is even. 
Lemma is proven.

Now, we can construct our adversary $\mathcal{A}$ as follows. Suppose $\mathcal{A}$ is given $(u,v,w)$. Then,
\begin{enumerate}
    \item Based on $u$, get the parity of $\alpha$, say $p_{\alpha} \in \{\text{even}, \text{odd}\}$.
    \item Based on $v$, get the parity of $\beta$, say $p_{\beta} \in \{\text{even}, \text{odd}\}$.
    \item Based on $w$, get the parity of $\gamma$, say $p_{\gamma} \in \{\text{even}, \text{odd}\}$.
    \item Calculate $p_{\gamma}'\in \{\text{even}, \text{odd}\}$ --- parity of $\alpha\beta$.
    \item Return $\widehat{b}=0$ if $p_{\gamma}' = p_{\gamma}$, and $\widehat{b}=1$, otherwise.
\end{enumerate}

Suppose $\gamma$ is indeed $\alpha \times \beta$. Then, condition $p_{\gamma}'=p_{\gamma}$ will always hold. 
If $\gamma$ is a random element, then the probability that $p_{\gamma}'=p_{\gamma}$ is $1/2$. Therefore, the 
probability that $\mathcal{A}$ will guess the bit $b$ correctly is $3/4$, and the advantage is $1/4$ therefore. 
\end{proof}

\subsubsection*{Pseudo-random Generators}

\textit{Read the following paragraph before solving Exercises 5--10}

We now introduce another fundamental primitive, the \textbf{pseudorandom generator} 
(PRG), and define its security using the same way as in \Cref{subsec:defining-security,subsec:security-reduction}.

\begin{definition}
    A \textbf{pseudorandom generator} (PRG) over $(\mathcal{K},\mathcal{X})$ is a deterministic, efficient algorithm 
    $G: \mathcal{K} \to \mathcal{X}$ that takes as input a \textbf{seed} $k \in \mathcal{K}$ and 
    outputs a string $x \in \mathcal{X}$. We additionally require $\#\mathcal{X}>\#\mathcal{K}$: this way, $G$ 
    \textbf{stretches} a short seed into a longer output.
\end{definition}

The point of a PRG is to act as a cheap substitute for true randomness: instead of sampling 
$\log_2 \#\mathcal{X}$ random bits directly, we sample a much shorter seed $k$ and expand it via $G$. For this 
substitution to be useful cryptographically, the output of $G$ must be impossible to 
distinguish from a genuinely random string of the same length, even though $G$ is completely 
deterministic. Informally, we write this as
\begin{equation*}
    \left[G(k): k \leftarrowS \mathcal{K}\right] \approx \mathcal{X}.
\end{equation*}
where $\approx$ denotes that no efficient algorithm can tell the two distributions apart. As 
before, we make this precise via a game.

\begin{definition}
    Let $G: \mathcal{K} \to \mathcal{X}$ be a PRG.
    Define the following game between a challenger $\mathcal{C}h$ and an adversary $\mathcal{A}$:
    \begin{algoen}
        \item $\mathcal{C}h$ flips a coin $b \leftarrowS \{0,1\}$.
        \item \textbf{if} $b = 0$: $\mathcal{C}h$ samples $k \leftarrowS \mathcal{K}$ and sets 
        $x \gets G(k)$. \\
        \textbf{if} $b = 1$: $\mathcal{C}h$ samples $x \leftarrowS \mathcal{X}$ directly. \\
        In either case, $\mathcal{C}h$ sends $x$ to $\mathcal{A}$.
        \item The adversary $\mathcal{A}$ outputs a guess $\widehat{b} \in \{0,1\}$.
    \end{algoen}

    We define $\mathcal{A}$'s \textbf{advantage in distinguishing output of $G$ from random}, denoted 
    $\text{Adv}^{\text{PRG}}_{\mathcal{A},G}(\lambda)$, as $\text{Adv}^{\text{PRG}}_{\mathcal{A},G}(\lambda) := \left| \Pr[b = \widehat{b}] - \frac{1}{2} \right|$.
\end{definition}

\begin{definition}
    We say that $G$ is a \textbf{secure pseudorandom generator} if for every efficient 
    adversary $\mathcal{A}$, the advantage $\text{Adv}^{\text{PRG}}_{\mathcal{A},G}(\lambda)$ is 
    negligible in $\lambda$.
\end{definition}

\begin{tcolorbox}
[ colback=blue!5!white, fonttitle=\bfseries, colframe=blue!80!white,
    title=Exercises 7--9. PRG Security through Statistical Tests]
    In this small paragraph, we give an alternative definition of PRG security that one might encounter in different sources. 
    Let $G: \mathcal{K} \to \{0,1\}^{\lambda}$ be a pseudorandom generator. We want to test if $G$ is secure using a function $\mathcal{A}: \{0,1\}^{\lambda} \to \{0,1\}$, which we call a \textit{statistical test}. The advantage of $\mathcal{A}$ is defined as:
\begin{equation*}
    \text{Adv}^{\text{PRG}}_{\mathcal{A},G}(\lambda) := \left|\underset{k \leftarrowS \mathcal{K}}{\text{Pr}}[\mathcal{A}(G(k))=1] - \underset{x \leftarrowS \{0,1\}^{\lambda}}{\text{Pr}}[\mathcal{A}(x)=1]\right|
\end{equation*}
We naturally require $\text{Adv}^{\text{PRG}}_{\mathcal{A},G}(\lambda)$ to be negligible for all efficient $\mathcal{A}$.
\end{tcolorbox}
